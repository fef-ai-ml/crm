# Web dashboard (plan J) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A marketer logs into `Crm.Web`, builds a nested segment with a live count, saves it with field-level errors, runs it and browses its members and runs, explores profiles and their timelines, and manages API keys — every screen of spec §7, proven by E2E-001…008 and the Zod half of CT-002.

**Architecture:** The existing Vite + React 19 shell (`src/Hosts/Crm.Web`) gains an in-memory JWT session with cookie refresh, a typed client generated from the committed `docs/api/openapi.json`, and four feature areas (`auth`, `segments`, `profiles`, `api-keys`) under TanStack Router + Query. The rule builder is a pure reducer over the exact JSON tree the API stores; a TypeScript walker that mirrors `RuleParser` byte-for-byte (messages, paths, order) is wrapped in a Zod schema and proven against the shared fixture directory. Nothing changes on the API side.

**Tech Stack:** React 19.3, TypeScript 5.9, Vite 8, TanStack Router 1.170 + Query 5.102, Tailwind 4 (hand-rolled primitives, cva + tailwind-merge — no shadcn CLI, no Radix), Zod 4.6, openapi-typescript (new, dev only), Vitest 5 + Testing Library 16 (jsdom), Playwright 1.63 (Chromium).

**Spec:** `docs/superpowers/specs/2026-09-15-crm-slice1-design.md` §7 (Web UI), §6 API rows, §8.1 error contract; ADR-0007 (auth model); BRD FR-19…FR-23 (`docs/brd/BRD.md:88-97`), FR-12/13 for CT-002. Test specification: E2E-001…008 (`docs/test/e2e-load.md`), CT-002 Zod half (`docs/test/architecture-contract.md:65`), new UT-059…UT-063 (this plan). Plans H and I's rulings hold; the API is not modified.

The walker mirrors `RuleParser.cs` exactly (read it; these are the rules): a non-object node → `unknown node type` at the node path; an object with `op` is a group (`op` not a string in `and|or|not` → `<path>.op` "unknown group operator", then treated as `and`); a `not` whose `children` array length ≠ 1 → `<path>` "not must have exactly one child"; any other group with < 1 children → `<path>` "group must have at least one child"; children are walked in order at `<path>.children[i]` AFTER the group's own errors (pre-order). Else `type` `"attribute"` / `"event"`, otherwise `<path>.type` "unknown node type". Attribute: key not matching `KEY_PATTERN` → `<path>.key` "key must match ^[A-Za-z0-9_]{1,64}$"; unknown `cmp` → `<path>.cmp` "unknown comparator"; value rules at `<path>.value`: `exists`/`not_exists` with a value present → "value is not allowed for this comparator"; `gt|gte|lt|lte`: missing → "value is required", non-number → "value must be a number"; `contains`: missing → "value is required", non-string → "value must be a string", longer than 256 → "value must be at most 256 characters"; `in|nin`: missing → "value is required", not an array / empty / > 100 / not all strings or all numbers → "value must be a non-empty array of strings or of numbers (at most 100)"; `eq|neq`: missing → "value is required", string (≤ 256 else "value must be at most 256 characters") / number / boolean accepted, anything else → "value must be a string, number or boolean" (H24); unknown cmp with a value → the scalar rules.
